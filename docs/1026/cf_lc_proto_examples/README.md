# D3 合成换道：原型示例

2026-10-27 更新。代码：[tools/cf_data/lane_change.py](../../../tools/cf_data/lane_change.py)。计划：[cf_sft_autovla_plan.md](../cf_sft_autovla_plan.md) §3 D3。

navtrain 随机 300 帧（seed 0），每帧左右各试一次，共 600 个候选。`ok_*` 是通过的全部 10 个，`fail_*` 是带轨迹的失败样本前 12 个，`offroute_*` 是路线检查拒掉的 3 个例子（图的画法不同，见下）。

`ok_*` / `fail_*` 每张图：左边是 t = 0 的前视图，右边是 BEV（自车坐标系，上为前）：
- 灰线：lane / lane connector；
- 紫色：日志车辆，实色是 t = 0，淡色是 t = 2.5 s；
- 灰点：专家 GT；
- 红线：设计的换道轨迹（T 是 smoothstep 总时长）；
- 橙色虚线：PDM 的 LQR + 自行车模型跟踪 4 s 后的轨迹；
- 绿色 ×：编码成 action token 再解码回来的轨迹。

`offroute_*`：BEV 范围放大到 110 m。蓝色是本车道，绿色是目标车道，橙线是 PDM 的路线中心线。目标车道的第一个出口用粗线画，在路线上的是绿色，不在的是红色。本车道的出口用点线画。

## 检查一览

按代码里的顺序：

| 检查 | 加入时间和原因 |
|---|---|
| 自车在 lane 里、离中心线 ≤ 1.75 m | 10-27：车道多边形包住了自车，但中心线可能从自车前方十几米才开始，投影被夹在起点上，设计轨迹第一步就跳出去（val `fe06df4a8eb45023`：0.5 s 走了 17.7 m，PDM 和跟踪都没拦住，是 token 往返误差 2.87 m 暴露出来的）。现在往回接上前驱（多半是路口里的 lane connector）再投影 |
| 有同向相邻车道，中心线间距 2.5–5 m | |
| 目标车道 5 s 内一直平行（`target_diverges`）| 10-26：右侧车道是右转专用道时，换道变成右转 |
| 每 0.5 s 走的距离和专家对得上（`geometry`，允许 max(0.5 m, 25%)）| 10-27：几何兜底。除了上面的跳变，还挡住了两种：车道间距在变时，设计轨迹被目标车道带着横向挪（原型里的几个 `geometry` 都是这种）；专家停着时纯横移（斜率检查只统计专家一步走 > 0.1 m 的步，漏了这种，val 上见过）|
| 路线（`off_route`）| 10-27：上一版的 `ok_03` 换进了左转专用道，而路线要直行 |
| 横移 / 前进 ≤ tan 20°（`too_sharp`）| 10-26 用 25°；10-27 看图后把 5 m/s 减速中并入、斜率正好 25° 的样本去掉，收到 20° |
| 横向加速度 ≤ 3.0 m/s² | 10-27：和速度反事实共用。专家 GT p99 2.56 / p99.9 3.31 |
| 路口：keep forward 且两条车道都直才允许穿过 | 10-26 |
| PDM NC / DAC / DDC | |
| LQR 横向跟踪误差 ≤ 1.0 m | 10-26：PDM 的 LQR 纵向本来就跟不紧，专家 GT 自己的总偏差中位就有 0.53 m，所以只量横向 |
| 间距 | |
| 红灯（`red_light`）| 10-27：metric cache 里没有红绿灯，从 `navsim_logs` 取。纵向照抄专家，专家在灯刚变时进路口的情况会原样带过来（事后检查 4942 条里 43 条，40 条专家自己也算闯）|

路线检查拒掉的样本里，车速 > 4 m/s 的 11 个逐个看过，都拒得对，分两类：
- 目标车道是转弯专用道，路线要直行：右侧车道只能右转 5 个（`offroute_b`，右车道 39 m 后拐进右侧路口），左侧车道只能左转 1 个（`offroute_a`）；
- 路线马上要转弯，换道方向反了：路线 9–42 m 后右转（或右偏）却往左换 4 个（`offroute_c`），路线 30 m 后左转却往右换 1 个。

导航指令和路线可能对不上：`offroute_a` 指令是 keep forward，路线其实 51 m 后右转。所以检查用路线，不用指令。

## 地图分不出实线和虚线

nuPlan 地图 `boundaries` 层有 `boundary_type_fid`，但车道之间的线基本都是 0。`offroute_a` 画面里两条车道中间明明是实线，地图里也是 0。路缘外沿都是 2。所以没法用地图挡住"压实线换道"。实线多半出现在路口前的转弯车道，这部分 `off_route` 能挡住一大半；剩下的挡不住。

## 逐张说明

- `ok_00`（拉斯维加斯 13.9 m/s）、`ok_06`（14.1 m/s）：宽直路上往左换道，干净。`ok_06` 是 T = 3.1 s 的快速换道，解码后横向最多滞后 0.67 m，终点一致。
- `ok_02`：拥堵路段 5.6 m/s 往右换道，斜率 19.6°，在上限以内但接近。
- `ok_03`：BEV 里横移看起来很小，因为自车车头比车道朝左偏了 9°。专家这时已经在往左并，这条等于"把左换道做完"。
- `ok_05`：路口前往左换道，纵向沿用专家的减速。
- `fail_11`（`alongside_t0`）：右车道旁边停着皮卡，拒绝正确。
- `fail_12`、`fail_13`、`fail_17`（`too_sharp`）：车速 0.8–1.0 m/s，横着挪。
- `fail_10`、`fail_19`、`fail_21`（`geometry`）：换道后半段每 0.5 s 比专家多走 0.8–1.4 m。目标车道在往外张开（或路口附近两条车道走向不同），设计轨迹被目标车道带着横向挪。`fail_19` 车速 7.8 m/s，9 m 后就是路口。

## 已知的局限

- 其他车按日志回放，不会对自车做出反应；PDM 只查前 4 s，间距检查查满 5 s。
- 大部分帧画面里没有换道的理由，理由只来自 suggestion（和 simlingo 第 1 类一样）。
- 所有样本都从"自车在车道中间附近"开始。闭环里每 0.5 s 重新规划一次，第二次规划时车已经在两条车道之间了，这种状态训练里几乎没有（只有 D4 的专家真实换道里有）。
- 压实线换道挡不住（见上）。
