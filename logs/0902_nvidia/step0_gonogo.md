## 0. 先把剖面常数在 NAVSIM 上重标了

CARLA 那套 `a_brake=3.0 / hard=8.0` **照搬会造出物理上不存在的反事实**。
navtest 4000 帧、36000 个逐步加速度实测:

```
|a| p50=0.45   p90=1.29   p95=1.50   p99=1.93   p99.9=2.44   m/s²
P(|a| ≥ 2.0) = 0.68%      P(|a| ≥ 3.0) = 0.04%      P(|a| ≥ 8.0) = 0.03%
减速侧（只看 a<0）: p50=0.46  p95=1.45  p99=1.82  p99.9=2.42
v0: p10=0.90  p50=4.83  p90=9.30  max=14.56 m/s
```

→ 取 `BRAKE −1.5`（减速侧 p95）、`HARD_BRAKE −2.5`（p99.9，实际天花板）、`ACCEL +1.5`。

## 1. 可行集 D 长什么样（base = GT 轨迹）

```
|D|=0     0.5%      ← 好事:说明常数没标偏。用 CARLA 那套这里会堆一大坨
|D|=1     2.2%
|D|=2    22.1%
|D|=3    21.4%
|D|=4    53.8%      ← 一半以上的帧"四档都可行"，知识那半在这些帧上不构成任何约束
有档不可评（路径不够长）  1.0%   ← centerline 续接生效，弃权率很低
```

**读数:D 不退化。** 空集只有 0.5%，说明 teacher 不会因为造不出可行档而集体弃权;
但 53.8% 全可行意味着**约束只在剩下 46% 的帧上真正起作用**。

⚠️ 按 flow §4.3 的"快慢两侧都可行 → 弃权"，这套 base 下弃权率是 **54.8%**。
   但那条规则针对的是**判决方向歧义**，触发器是"学生轨迹不可行"——
   GT 上触发率是 0（见下），所以这个 54.8% 不能直接当成 teacher 的弃权率读。

## 2. GT 轨迹本身不可行 = **0.00%**（n=0 / 1490）

意料之中但值得写下来:GT 就是当时实际发生的事，对着 logged agents 重放，
**永远不碰撞、永远在可行驶区域内**。

→ 触发器 `1[ŷ 不可行]` **只可能在学生自己的 rollout 上点火**。
  这条从数据上确认了方法必须 on-policy —— 拿 GT 当 base 做这一步是没有意义的。

## 3. GT 的 `<PLAN>` 说法不在 D 里:**5.3%**

```
STOP        n=256   在 D 里 98.4%
DECELERATE  n=267   在 D 里 97.8%
KEEP        n=583   在 D 里 93.7%
ACCELERATE  n=384   在 D 里 91.7%
```

🔴 **别把这 5.3% 直接当成"GT 标签错了"（门1 的证据）。** 有相当一部分是
**剖面幅度的近似误差**:我们合成的是**恒定** a=+1.5 的加速档，而 NAVSIM 上
|a| 的中位数只有 0.45。GT 说 ACCELERATE、实际温和加速没事，而"+1.5 持续 5s"
撞上了 —— 判出来的是"这个幅度不行"，不是"加速这个决定不行"。
ACCELERATE / KEEP 的错位率（8.3% / 6.3%）明显高于 STOP / DECELERATE（1.6% / 2.2%），
方向也与这个解释一致。

**这是目前最大的一个待解决设计问题**:D 的语义取决于剖面幅度怎么定。
候选改法 —— 幅度不写死，按场景标定（加速档以前车间隙/限速为上界，
减速档以"停在冲突点前"为下界），而不是一个常数 a。
这件事要在触发率量出来之后一起定，因为它同时影响 D 和 chg。

## 贪心对照（T=0.01，G=1，同样那 600 帧）

```
                        PDMS      不可行率
greedy   (T=0.01)      0.7688      16.2%
mean-of-5 (T=0.9)      0.7337      19.9%   ← 逐条独立评分后对 3000 条取平均，不是 best-of-N
best-of-5 (T=0.9)      0.9095       4.3%   ← "5 条全不可行"的帧才算失败
```

**① 触发率不是采样噪声造出来的。**
贪心 16.2% vs T=0.9 的 19.9%，只差 3.7pp。这个中途权重的模型**本身**就有 16% 的帧
开出可行驶区或撞车（DAC=0 12.8% / NC=0 4.5%，仍然是横向为主）。
→ 前面那条"触发器只认 NC=0"的结论不受温度影响，依然成立。

**② ⭐ "能力在，但没被引出" —— 这是 AutoVLA 上的存在性证据**

```
best-of-5 − greedy   = +0.1407     采样里存在、而贪心拿不到的空间
greedy − mean-of-5   = +0.0351     T=0.9 的探索噪声代价（很小）
best-of-5 严格优于 greedy 的帧      62.2%
greedy 不可行 16.2%  →  5 条全不可行只有 4.3%
```

贪心失败的帧里，**大部分在采样中有救**（16.2% → 4.3%）。
探索的代价只有 0.035，而重排序的收益有 0.141 —— **差了 4 倍。**
模型不缺开好车的能力，缺的是把概率质量放对地方。
GRPO 要做的正是这件事，这 0.141 就是**不需要学任何新能力、纯靠重新排序**的上界。

> 这条和 `docs/0830/abstract.md` 里 "Sampling shows the capability is present but not
> elicited" 是同一件事，只不过那句是 simlingo/CARLA 的版本，这里是 AutoVLA/NAVSIM 的。

**③ 自洽度随温度变化**

```
m_consistency   greedy +0.957（一致 97.8%）   T=0.9 +0.819（一致 90.9%）
off-format 率   两者都是 0.00%
```

§7 的因果验证要对比的是 **greedy 的 +0.957**（评测口径），
而 RL 训练里看到的是 +0.819（rollout 口径）。别混用。

⚠️ 全部数字都基于 **2/6 epoch**（`epoch=1`，0-indexed）的权重，且在 **navtest** 上量。
   SFT 收敛后要重测。

# 横向失效的归因:是模型，不是 tokenizer（2026-09-02 19:45）

脚本 [tokenizer_ceiling.py](tokenizer_ceiling.py) · n=600（同一批 navtest token）

"69.5% 的失效是横向"之后要问的下一个问题:**是模型方向学不好，还是 action codebook
根本表达不了那个精度？** 轨迹是量化成 codebook token 输出的，如果 codebook 本身就差
半米，那天花板不在模型，改 reward 也没用。

把 **GT 轨迹**过一遍 tokenize → detokenize（就是训练时喂给模型的监督目标本身），再送评分:

```
                  PDMS      NC=0     DAC=0
GT 原始轨迹       0.9478    0.00%    0.00%
GT 量化再还原     0.9248    0.00%    2.17%

量化引入的最大横向误差   p50=0.04   p90=0.18   p99=0.29   max=0.41 m
```

**结论:tokenizer 不是瓶颈。** codebook 能把 GT 还原到横向 p90 = 18cm，
只有 2.17% 的帧因为量化翻成 DAC=0。而模型（epoch=1）是 12.83% ——
**其中 2.17pp 是 tokenizer 天花板，剩下 ~10.7pp 是模型自己的横向精度。**

顺带拿到两个有用的上界:

```
PDMS 上界   0.9248（量化后的 GT）—— 不是 1.0，GT 自己也只有 0.9478（EP/comfort 拿不满）
模型 greedy 0.7688（epoch=1）    —— 距上界还有 0.156
```

⚠️ 这个 0.9248 才是 PDMS 的正确参照，**不要拿 1.0 当满分去算相对差距**。

# epoch=1 vs epoch=2 —— 横向失效会不会靠继续训练自己好（2026-09-02 20:15）

同一批 600 帧、同样 greedy（T=0.01, G=1）。
`epoch=` 是 0-indexed:ep1 = 训了 2/6，ep2 = 训了 3/6。

```
                      ep1 (2/6)    ep2 (3/6)      Δ
val loss              0.5147       0.4732       −0.0415
PDMS                  0.7688       0.7779       +0.0091
不可行率              16.17%       15.67%       −0.50pp
  NC=0（碰撞）         4.50%        3.67%       −0.83pp   相对 −18%
  DAC=0（横向）       12.33%       12.33%       −0.50pp   相对  −4%
chg                   13.83%       13.50%       −0.33pp
D 为空(占不可行)       12.4%         8.5%       −3.9pp
m_consistency         +0.957       +0.933       −0.024
```

## ① loss 掉了，PDMS 几乎没动

loss −0.042 换来 PDMS +0.009。按这个斜率再训 3 个 epoch 也就到 ~0.805，
离量化后 GT 的上界 **0.9248** 还差得远。
**横向失效不是简单的欠训练。**

碰撞侧相对降 18%、横向侧只降 4% —— 两条腿收敛速度差一个量级。

## ② ⭐ 但【严重程度】明显下降了

```
出界深度（整条 5s）      ep1                    ep2
   p50               1.32 m                 1.15 m
   p90               4.69 m                 2.91 m     ← 深尾巴砍掉近一半
   ≤0.3m 的占        22.1%                  33.8%      ← 擦边占比上升
```

**训练消掉的是"开得很偏"那批，"轻微蹭出"没怎么动。** 残余失效越来越集中在擦边。

这直接反映在闸门上:

```
触发器定义                              ep1 触发/chg      ep2 触发/chg
现状 NC=0 或 DAC=0                    16.17% / 13.83%   15.67% / 13.50%   −2%
只认 NC=0                              4.50% /  3.50%    3.67% /  3.00%  −14%
★ NC=0 或 (DAC=0,深度>0.3m,首次≤3s)     9.50% /  7.83%    7.67% /  6.83%  −13%
```

不加闸门 chg 只降 2%，加了闸门降 13% —— **闸门滤掉的和训练在改善的是同一批**，
两者口径一致。反过来说:**越往后训，不加闸门的 chg 里噪声占比越高。**
所以闸门不是可选项，是随收敛越来越必要。

## ③ 归因

结合 tokenizer 天花板那一节:

```
DAC=0 12.33%（ep2）
  ├─ 2.17pp   codebook 量化的天花板（GT 量化后就有）
  └─ ~10.2pp  模型自己的横向精度
              且训练 1 个 epoch 只降 0.5pp、但深度 p90 降 38%
```

→ **是模型的横向精度问题，不是表示能力问题**;而且它降的是"偏多少"，不是"偏不偏"。

```
   D = HARD_BRAKE, BRAKE            68.2%
   D = HARD_BRAKE                   13.6%
   teacher 会改成 —— 更慢 77.3% | 更快 0.0% | 不用改 18.2% | 弃权 4.5%

```

## ✅ 对照组:机制不滥杀

506 条可行 rollout 上 teacher **95.8% 不出手**，D 有一半是四档全可行。假阳性不是问题。

## ✅ 碰撞上:对症

D 塌成 `{HARD_BRAKE, BRAKE}`、判决"更慢" —— 这就是正确答案。

## 🔴 横向上:处方一模一样，但理由是伪的

更慢 77.8%，和碰撞的 77.3% **几乎不可区分**。
D 之所以非空，是因为**刹车让车在 4s 窗口内走不到出界的那一段**。
teacher 学到的是"你转向不准，那就别开那么快"。

→ **机制本身没坏，坏在触发器把两类问题混在一起，而速度剖面在原理上分不开它们。**
  不加闸门的话，72/94 = **77% 的刹车教学是因为错误的理由**。

## 决定

**先缩到 NC 那一条腿（方案 A）**:触发器只认 `NC=0`（+ TTC）。
chg 降到 3.0%（greedy）/ 约 4–5%（T=0.9 的 RL rollout，NC=0 在 T=0.9 下是 6.07%）。
按 G=5、navtrain 10 万帧算，一个 epoch 仍有上万次 chg 事件，信号量足够，
而**每一次出手都对症** —— 方法要证明的因果链是干净的。

深度/时刻闸门（方案 B，chg 6.83%）是折中，里面仍混着横向的伪修复，不作主线。
PATH 轴（方案 C）见下一节。

# 方案 C:把 PATH 轴纳入反事实 —— 策略与验证（2026-09-02 21:00）

## 先验证核心假设

对那 72 条只 DAC=0 的横向失效，造一条**同样配速、但跟住 centerline** 的候选:

```
可行                        47   65.3%
可行且 PATH 与学生所说一致    41   56.9%   ← 话说对了，是开得不准
可行但 PATH 不同              6    8.3%   ← 真正该给 PATH 判决的
仍不可行                     25   34.7%
```

**56.9% 的横向失效里，学生说的那对词本身是可行的。** 这正是 teacher 应该**弃权**的情形，
而现在它在开刹车。

## 核心重构:D 从「剖面集合」改成「标签集合」

不是"加一个轴"，是把成员资格的定义改对。

```
现在   D ⊆ {4 个速度档}
       成员资格 = 沿【学生自己那条路径】以该加速度配速，可不可行
       🔴 路径被钉死在学生（可能已经偏出）的路径上
          → 标签的对错 和 执行的精度 被搅在一起

改成   D ⊆ {SPEED} × {PATH}   (4 × 3)
       成员资格 = 【存在】一条带该标签的可行轨迹
```

语义这才对:**DriveDiRL 只给【语言】定价**，所以 D 该问的是"这句话说得对不对"，
而不是"你这条轨迹开得准不准"。现在的定义把后者混进来了，才会在执行误差上开速度处方。

## 候选族（Frenet，锚在 centerline 上）

| 横向 3 档 | 造法 |
|---|---|
| `AS_IS` | 学生自己的横向剖面 d(s) |
| `CENTER` | 跟住 centerline，d=0（验证:65.3% 的横向失效在这档变可行）|
| `OFFSET±` | centerline ± 一个车道宽（~3.5m），造真正的变道候选 |

纵向沿用现有 4 档（HARD_BRAKE −2.5 / BRAKE −1.5 / KEEP 0 / ACCEL +1.5，已按 NAVSIM 重标）。
组合 3 × 4 = 12 条候选。

🔴 **标签必须实测，不能假设。** 每条候选合成后用**同一个 `plan_from_track`** 打标签再落格 ——
我们的 PATH 是"净横向位移比 ≥ 0.20"，不是转向指令，所以"CENTER 档 = STRAIGHT"是错的假设。
某个格造不出来就标 `unrealizable` → **弃权，不能当成"不可行"**（fail-open 的老坑，flow §4.3）。

## 判决规则

```
学生的 (speed, path) ∈ D   → 弃权    "说得对，是开得不准"
只有一个轴需要改            → 沿该轴取最近可行标签
两个轴都要改               → 弃权    一次只教一件事
D 为空                     → 弃权
```

## 成本控制

12 次 PDMScorer vs 现在 4 次 = 0.6s/帧，G=5 → 3s/step，**对 online RL 太重**。

短路:**先只算学生自己那一格**，可行就直接弃权、其余 11 格不算。
对照组 84% 的 rollout 会在这里短路掉 → 平均成本接近 1 次评分。
剩下的只算相邻格（每轴 ±1，5–6 格）。

## 预期效果

```
72 条横向失效  →  56.9% 正确弃权 | 8.3% 给出真 PATH 判决 | 34.7% 弃权
22 条碰撞      →  不受影响，仍是"更慢"
```

## 两个已知风险

1. **centerline 不总是对的参照** —— 变道场景 GT 本来就该偏离它。
   那 34.7% 里应该有一部分是这个，要看 `route_lane_ids` 有没有包含相邻车道。
2. **高速下某些标签格物理上造不出来**（横向位移比达不到 0.20）→ 必须走 unrealizable 弃权。

# 📌 定案:AutoVLA/NAVSIM 的定位（2026-09-02 21:30）

## 语言通道 vs 执行通道的分账

```
n=600（ep2 greedy）  当前 PDMS 0.7779   量化后 GT 上界 0.9248   总剩余空间 +0.1469

  NC=0 碰撞          n= 22 ( 3.67%)   ΔPDMS ≤ +0.0335
    └ 说法也错了      n= 18 ( 3.00%)   ΔPDMS ≤ +0.0274
  只 DAC=0 横向      n= 72 (12.00%)   ΔPDMS ≤ +0.1107
    └ 说法也错了      n= 63 (10.50%)   ΔPDMS ≤ +0.0968   ← 🔴 这部分是假的
```

那 +0.0968 假在哪:上一节验证过，**56.9% 的横向失效在给了 centerline 候选后，
学生说的那对词就变成可行的了** —— 说法本来没错，错的是执行。

真正的分账:

```
★ 真·决策错误（NC，说法确实错了）   +0.0277    占总空间 19%
★ 横向执行精度                     +0.1107    占总空间 75%
```

**75% 的空间是任何 (SPEED, PATH) 词都表达不了的。**
`078bc1027dde5d1a` 说 ACCELERATE,RIGHT —— 方向对、GT 也右转，错的是转弯半径;
`9900336c08095d0f` 说 KEEP,LEFT —— 也对，错的是横向跟踪。
这两个不论反事实是 speed-only 还是 speed+path，**正确行为都是弃权**。
方案 C 的价值是"让 teacher 正确地不出手"（去噪），不是增益。

## 决定:走路线 ②

**主结果留在 simlingo / CARLA;AutoVLA / NAVSIM 作为迁移性证据。**

理由不是方法不成立，是**载体不匹配**:NAVSIM 开环、非反应式、4s LQR 跟踪，
失效自然以执行精度为主;CARLA 闭环有交互，决策错误占比高得多。
DiRL 在 NAVSIM 上的作用域是 3% 的 rollout / +0.028 PDMS，
**DiRL vs 普通 GRPO 的对照臂大概率测不出显著差异** —— 不做 ablation 是对的。

产出形式:
- **一张 table**（不做 ablation）
- **两张 visualization**:展示反事实合成出的**可行解**

# teacher 三块落地 + 定标（2026-09-02 22:30）

代码:[`models/utils/teacher.py`](../../models/utils/teacher.py)（触发器 / splice / 判决）
+ `models/autovla.py::teacher_terms` / `_span_nll_pair`（Δ 定价）。
**默认关闭**，开关 `rl.teacher.enable`。

## 🔴 踩到的坑:只改 tag 是错的

第一版 splice 只换 `<PLAN>` 里的 SPEED 词。实测:

```
"I should speed up: <PLAN>ACCELERATE,STRAIGHT</PLAN>"  → 只把 tag 换成 KEEP
   nll(z)  = -0.0000     ← 给定前缀 "I should speed up: <PLAN>"，ACCELERATE 几乎确定
   nll(z*) = 23.8750     ← 造出的是一个自相矛盾的句子
   Δ = +23.9
```

**句子在 tag 之前就用自然语言把决策说了一遍。** 只改 tag，Δ 量到的是"矛盾程度"，
不是"模型对被纠正的判决有多抗拒"。

⚠️ 我之前说"AutoVLA 的 tag 是结构化的，不会像 simlingo 那样造病句"——**这句话是错的**。
   tag 结构化只解决了"定位"，没解决"散文也复述了决策"。**同一个坑，没有豁免。**

修法:散文动词和 tag 一起改（模板可枚举，与 `navsim_agent_qa.py::_speed_verb` 同步）:

```
STOP        remain stopped (v0<2.0) | come to a stop
DECELERATE  slow down
KEEP        hold my current speed
ACCELERATE  speed up
                    + 可选 " and bear left/right"（PATH 后缀原样保留）
```

修完同一帧:`nll(z)=0.368  nll(z*)=0.250  Δ=−0.118` → clip 到 0，不罚。
**改写后反而更自然 = 模型没有抗拒 = 不该付代价**，语义对了。

Δ 的 span 也跟着从"tag 里那个词"扩到**整个决策从句**（`I should …: <PLAN>…</PLAN>`，
约 10 token），因为两处都改了，只量一处会漏。整条 completion 是 107 token。

## Δ 的分布 → 权重定标

navtest 80 帧 × G=5 = 400 rollout（ep2，trigger=`nc_or_deep_dac`）:

```
触发 8.25%   chg 5.50%   （与离线算的 7.67% / 6.17% 一致）

Δ = nll(z*) − nll(z)    n=22
   p5 −0.088   p50 +0.413   p95 +0.608   max +0.628   mean +0.340
   Δ ≤ 0（不罚）占 13.6%
   clip_c=2.0 截断 0.0%    clip_c=1.0 截断 0.0%    clip_c=0.5 截断 31.8%

改写方向 KEEP→DECELERATE 10 | KEEP→STOP 5 | ACCELERATE→STOP 2 | ACCELERATE→KEEP 2
```

| 参数 | simlingo 的值 | 改成 | 依据 |
|---|---|---|---|
| `clip_c` | 2.0 | **1.0** | Δ 最大 0.628，2.0 **从不生效**，是个没接上的保险丝 |
| `w_say` | 0.5 | **0.2** | 0.5×0.34 = 0.17 是组内 PDMS std（0.039）的 **4.5 倍**，语言项会主导 advantage。0.2 → 均罚 0.068 ≈ 1.7×，量级可比 |
| `w_viol` | 1.0 | 1.0 | ⚠️ 作用不同:simlingo 的 reward 是 −ADE（负分），不加罚会让违规样本(0) 排到可行样本(−ADE) 之上、排序反掉;这边 PDMS∈[0,1]，不可行本来就拿 0、已在组内垫底，w_viol 只加大区分度 |

## 顺手修的两处

**`get_per_token_logps` 的显存**:原来 `log_softmax(logits)` 会把 (B, L, V=152064)
materialize 成 float32 —— G=5 时 3.5 GB，只为每个位置取一个数。
改成 `gather − logsumexp`（V 维直接规约掉），数值差 4.8e-7。**主训练路径同样受益。**

**不再静默吞异常**:`teacher_terms` 原来 `except: continue`。Δ 一直失败的话
`chg` 恒为 0、训练照跑，而定价通路其实从没生效 —— 正是这次差点没发现的坑。
现在首次失败打印 + 计 `delta_error`。
